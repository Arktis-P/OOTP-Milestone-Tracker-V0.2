# OOTP Milestone Tracker V0.2 — Project Rules & Workflow Guidelines

## 1. 사용자의 기본 작동 원칙 (User Core Directives)
- **최소 토큰, 최고 완성도**: 모든 작업은 최소한의 토큰 소비로 최상급 품질로 완수한다.
- **적절한 서브에이전트/하위 모델 사용**: 필요 시 하위 모델을 서브에이전트로 호출하되, 구현 대상을 중복 검증하거나 상위 모델이 하위 모델에 적합한 단순 작업을 반복하지 않도록 효율적으로 관할한다.
- **간결한 보고**: 작업 중에는 진행 중인 단계를 간단히 표시하며, 수식어나 중복 설명을 최소화한다.
- **체크포인트 커밋**: 의미 있는 단위 작업(체크포인트)이 완료될 때마다 Git 커밋을 진행하여 작업 추적이 가능하게 한다. 최종 완료 후 작업 내용을 간단히 요약한다.
- **명확한 자율 진행 & 모호점 질문**: 권한이 필요한 작업은 자율 진행하되, 설계상 결정이 필요한 모호한 부분은 임의 판단하지 않고 사용자에게 선택지(옵션)로 전달해 결정받는다.

## 2. 프로젝트 개발 및 아키텍처 원칙 (Project Architecture & Policy)
- **계층 분리**: GUI(PyQt/PySide 등)와 독립된 `core/` 백엔드를 먼저 구축하고 단위 테스트를 수행한다.
- **OOTP 입력 읽기 전용**: OOTP 원본 파일은 항상 Read-Only 입력으로 처리한다.
- **멱등성(Idempotency)**: 동일한 데이터를 여러 번 import하더라도 기록이 중복 생성되거나 변형되지 않는다.
- **세이브 격리(Save Isolation)**: 세이브별 SQLite DB를 분리(WAL 모드)하여 데이터가 섞이지 않도록 보장한다.
- **정책 분리**: 마일스톤 기준, 연속 기록, 예측 공식 등은 외부 CSV/JSON 정책 파일(`data/`)로 관리한다.
